# Anti-Raid Bot — защита от накрутки + веб-капча на вход

Бот для группы/канала: сам детектит резкий всплеск вступлений (похоже на накрутку),
проверяет каждого нового участника по чёрным спискам и эвристикам, и включает капчу
на вход — сам или вручную. Плюс полноценная админ-панель: доверенные пользователи,
баны, антифлуд, статистика, журнал действий.

Капча — это **Telegram Mini App** (веб-страница внутри Telegram, в стиле NFT-маркетплейса
Telegram: тёмный градиент, стеклянные карточки, анимации), а не кнопки прямо в чате.

Апдейты бот получает через **вебхук** (не polling) — на том же веб-сервере, что раздаёт мини-апп.

## Что делает

### Антирейд и капча
- **Автодетект накрутки.** Считает вступления за скользящее окно (по умолчанию 5 за 30 сек).
  Если порог превышен — сам включает капчу на `RAID_CAPTCHA_DURATION` секунд (по умолчанию 15 мин)
  и пишет владельцу в личку. Пока рейд активен — раз в минуту напоминание, пока не снимут вручную
  или он не истечёт сам.
- **Экстренный авто-бан.** Отдельный, более жёсткий порог поверх обычного антирейда: если за
  `EXTREME_RAID_WINDOW_SECONDS` (по умолчанию 30 сек) в чат ломится `EXTREME_RAID_THRESHOLD`
  и больше человек (по умолчанию 10) — капча уже не спасёт, бот сразу **банит всех**, кто попал
  в этот всплеск. Работает и для группы, и для канала: если люди подписываются напрямую —
  реальный бан и удаление из канала; если у канала включено «Одобрение новых подписчиков» —
  вместо (или вместе с) этим отклоняет все висящие заявки разом. Отчёт о том, сколько
  забанено/отклонено, приходит владельцу отдельным сообщением, каждый бан попадает в бан-лист
  чата с причиной «экстренный авто-бан» — если зацепило кого-то не того, разбанить можно оттуда.
  Доверенных пользователей (см. ниже) этот бан не касается, даже если они попали в тот же
  всплеск.

  Список «кого банить» бот держит в памяти процесса, а не берёт из базы данных — при
  настоящем массовом рейде (сотни вступлений за секунды) запись в SQLite физически не
  успевает под такой нагрузкой, и если бы список брался из базы, часть рейдеров могла бы
  остаться незабаненной просто потому, что их ещё не успели записать на диск. Баны при
  этом идут параллельно (до 20 одновременно), а не по одному, — иначе сотни банов растянулись
  бы на минуты.
- **Приветствие без капчи.** Если для группы капча выключена (или пользователь в списке
  доверенных — см. ниже) и капча ему в принципе не показывается, вместо тишины бот сразу
  пишет в чат приветствие с видео и упоминанием — то же самое видео и стиль, что и при
  успешном прохождении капчи, просто без самой проверки.
- **Автоудаление системных сообщений.** Нативные "X присоединился к группе" / "X вышел из
  группы" от самого Telegram удаляются через `SERVICE_MESSAGE_DELETE_SECONDS` (по умолчанию
  20 сек) — держат чат чище, особенно при частых вступлениях/выходах. Требует у бота право
  "Удаление сообщений"; без него просто ничего не делает, никак не ломается.
- **Защита от отложенной правки.** Классический трюк накрутки: написать безобидное сообщение,
  дождаться доверия/охвата, потом отредактировать в рекламу/скам. Если правят сообщение старше
  `EDITED_MESSAGE_AGE_THRESHOLD_SECONDS` (по умолчанию сутки) — бот его удаляет. Админов чата
  (настоящих Telegram-админов, не только владельца бота) не трогает никогда.
- **Веб-капча на вход:**
  - В **группе** — новый участник получает ограничение на отправку сообщений и кнопку
    «🔓 Пройти проверку». Кнопка ведёт в личку с ботом, там открывается мини-апп с примером
    (4 варианта ответа). Не решил за `CAPTCHA_TIMEOUT_SECONDS` (по умолчанию 90 сек) — кик
    (можно зайти заново).
  - В **канале** — два способа, можно использовать оба сразу:
    1. **Персональная ссылка бота (рекомендуется).** В карточке канала в панели — кнопка
       «🔗 Ссылка для входа через бота» (`t.me/<бот>?start=join_<chat_id>`). Разошли её вместо
       обычной ссылки на канал. Пользователь сначала попадает в бота, проходит капчу и только
       потом получает одноразовую ссылку на канал (`member_limit=1`). Проблемы «бот не может
       написать первым» тут нет — переход по ссылке и есть запуск бота.
    2. **Обычная заявка на вступление** (если у канала включено «Одобрение новых подписчиков»).
       Бот пишет пользователю в личку с кнопкой капчи и одобряет заявку сразу после неё.
       ⚠️ Если человек никогда не писал боту — заявка повиснет и через `REQUEST_DECLINE_SECONDS`
       (по умолчанию час) сама отклонится. Это резервный вариант, основным лучше сделать способ 1.
- **Ручное управление** — можно включить капчу заранее командой/кнопкой, независимо от автодетекта.

### Чёрные списки и эвристики
- **CAS (Combot Anti-Spam)** — при каждом вступлении/заявке/переходе по ссылке ID сверяется
  с публичной базой известных спам-ботов [cas.chat](https://cas.chat). Если найден — бан/отклонение
  сразу, без капчи. Если сеть недоступна — не блокируем человека из-за нашей же ошибки.
  Выключается через `CAS_ENABLED=false`.
- **Эвристики подозрительности** — если капча для чата выключена, но у нового участника
  одновременно шаблонный юзернейм (`user18234756` — слово + 5+ цифр) **и** нет фото профиля,
  капчу всё равно покажем именно ему — выборочно, не трогая остальных. `HEURISTICS_ENABLED=false`
  выключает совсем.
- **Антифлуд по сообщениям** — если участник шлёт подряд много сообщений (`FLOOD_MESSAGE_THRESHOLD`,
  по умолчанию 6 за `FLOOD_WINDOW_SECONDS`=10 сек) или повторяет одно и то же (`FLOOD_REPEAT_THRESHOLD`,
  по умолчанию 3 раза) — мут на `FLOOD_MUTE_SECONDS` (по умолчанию 5 мин), сообщение удаляется,
  владельцу приходит уведомление. Не трогает админов и доверенных. Переключается в карточке
  каждой группы отдельно.
- **Доверенные пользователи** — глобальный список (не привязан к чату): капча/CAS/эвристики/
  антифлуд им не показываются вообще нигде. Это же список — белый список для массовых
  действий: **экстренный авто-бан** и **массовый бан по времени вступления** (см. ниже)
  доверенных не трогают ни при каких условиях, даже если формально попадают под условия
  всплеска или временное окно. Управляется из раздела «Другое» → «🤝 Доверенные».

### Приватность
- **Приватный бот.** В личке бот отвечает нормально только владельцу (ID из `ADMIN_IDS`).
  Все остальные вместо меню/панели получают сообщение «Этот бот принадлежит `OWNER_CONTACT`».
  На саму капчу это не влияет — она обязана работать для любого пользователя, иначе никто,
  кроме владельца, не смог бы подтвердиться и войти в чат/канал.

### Оформление: премиум-эмодзи
- Приветствие в группе, сообщение об успехе и кнопка «Пройти проверку» в личке используют
  **премиум-эмодзи** (Bot API 9.4, `<tg-emoji>` в тексте и `icon_custom_emoji_id` на кнопке).
  ID эмодзи задаются в `EMOJI_WAVE_ID` / `EMOJI_CHECK_ID` / `EMOJI_GHOST_ID`.
- ⚠️ Премиум-эмодзи показываются, только если у **владельца бота** (аккаунта, на который
  зарегистрирован токен) есть подписка Telegram Premium. Это не настройка бота, а требование
  самого Telegram. Если Premium нет — Telegram отклоняет отправку, и бот **автоматически**
  откатывается на обычные юникод-эмодзи (👋 / ✅) и кнопку без иконки — ничего не ломается,
  просто выглядит чуть проще.
- **В админ-панели эмодзи убраны почти везде** — оставлен только статус-индикатор чата
  (`✅ / ❌ / ⚠️ / ⛔️` в шапке и списках) и `🔴 / 🟢` в строке состояния рейда. Все остальные
  кнопки, заголовки и всплывающие подтверждения — чистый текст.

### Видео в капче
- Приглашение «Проверка для чата/канала «...» готова, жми кнопку» (личка, `start.py`) и
  сообщение об успехе в группе (`server.py`) отправляются не текстом, а **видео с подписью**
  (`assets/chat.mp4` и `assets/prew.mp4` соответственно, играются как гифки — автовоспроизведение,
  без кнопок плеера). При первой отправке файл заливается в Telegram, дальше переиспользуется
  готовый `file_id` — повторно не перезаливается. Если видео почему-то не ушло — есть фолбэк
  на обычное текстовое сообщение с той же кнопкой, бот не падает.
- Хочешь заменить ролики — просто перезапиши `assets/chat.mp4` / `assets/prew.mp4` (тот же путь
  и имя) и перезапусти бота: старый `file_id` живёт только в памяти процесса, после рестарта
  зальётся новый файл.

## Как устроена веб-капча технически

- В боте поднят `aiohttp`-сервер (`server.py`), который раздаёт статику мини-аппа (`webapp/`),
  принимает вебхук от Telegram и отвечает на два запроса капчи:
  - `GET /api/challenge?token=...` — отдаёт вопрос капчи и варианты ответов
  - `POST /api/verify` — принимает токен, ответ и `initData` от Telegram WebApp,
    **проверяет подпись initData по HMAC-SHA256** (по алгоритму из документации Telegram) —
    без этого подделать проверку было бы тривиально. Дальше сверяет, что подписанный
    Telegram user id совпадает с тем, для кого создавалась капча, и только тогда снимает
    ограничение / выдаёт ссылку / одобряет заявку.
- Сессии капчи (вопрос, правильный ответ, кому она принадлежит) живут в памяти процесса
  и одноразовые — токен нельзя переиспользовать.
- Мини-апп — статические `webapp/index.html`, `webapp/style.css`, `webapp/app.js`, без сборки.
  Фон — звёздное небо (белые точки на чёрном), рисуется на `<canvas>` в JS, без картинок/видео.
  Иконки состояний (ожидание/вопрос → звезда, успех → галочка, ошибка → крестик) — Lottie-анимации
  из `webapp/lottie/*.json`, рендерятся через `lottie-web` (библиотека вшита в проект как
  `webapp/lottie-web.min.js` — не тянется с CDN, чтобы капча не зависела от стороннего хостинга).

## Команда /start — панель управления

Владелец (ID из `ADMIN_IDS`) в личке с ботом видит:

**🎛 Меню управления** → три раздела: **📡 Каналы**, **👥 Группы**, **🗂 Другое**.

- **Каналы / Группы** — список чатов, где бот админ, каждый пункт — кнопка вида
  `Название ✅/❌/⚠️/⛔️` (✅/❌ капчи для групп, ✅ = «всё ок» для каналов, ⚠️ = рейд,
  ⛔️ = вход закрыт всем). Внизу — кнопка **➕ Добавить канал/группу**: пришли @username, ID
  или перешли сообщение оттуда — нужно для чатов, добавленных до этого функционала, или
  если Railway пересоздал файловую систему без Volume (см. ниже).

  Карточка чата:
  - включить/выключить капчу (для групп)
  - ⛔️ закрыть вход всем / 🔓 открыть обратно
  - 🔔/🔕 уведомления о новых/ушедших участниках
  - 🛡/⚪️ антифлуд по сообщениям (для групп)
  - для каналов — ссылка-приглашение через бота
  - сводка активности, счётчик участников и забаненных
  - **👥 Участники** — постранично, с поиском по юзернейму/имени; карточка участника:
    юзернейм, ID, дата вступления, кнопки **Перейти в профиль** / **Удалить** (кик) / **Забанить**
  - **🚫 Забаненные** — кто, когда, за что, с кнопкой разбана
  - **📈 Статистика** — вступления/выходы за 7 дней текстовым графиком
  - **📜 Журнал** — кто из админов (или бот автоматически) что сделал и когда
  - **Массовый бан по времени вступления** — выбираешь окно (30 минут / 1 / 2 / 3 / 6 / 12 /
    24 часа), бот показывает, сколько человек под него попадает, после подтверждения банит
    и удаляет их всех из чата по одному через Telegram API (с небольшой паузой между запросами,
    чтобы не словить рейт-лимит) и присылает отдельным сообщением отчёт: сколько забанено,
    у скольких не получилось (например, уже вышли сами). Каждый попадает в бан-лист чата
    с причиной вида «массовая чистка: вступил за последние 2 часа» — оттуда его можно
    разбанить, если зацепило кого-то не того.
- **Другое** — добавить бота в группу/канал, **🤝 Доверенные пользователи**, помощь.

## Команды (только для ID из ADMIN_IDS)

Дублируют часть кнопок панели — на случай, если панель уже закрыли.

| Команда | Что делает |
|---|---|
| `/captcha on` / `/captcha off` | Включить/выключить капчу вручную в текущем чате |
| `/captcha_auto` | Вернуть управление капчой автоматике (антирейду) |
| `/raid_status` | Текущее состояние: капча, рейд, счётчик вступлений |
| `/raid_off` | Досрочно снять авто-режим рейда |

## Установка

1. Создай бота у [@BotFather](https://t.me/BotFather), получи токен.
2. Добавь бота в чат/канал **администратором** с правами:
   - в группе: «Блокировка участников» (ban) — для кика по таймауту капчи/антифлуда
   - в канале: «Добавление участников» / управление заявками на вступление
3. Скопируй `.env.example` → `.env`, заполни `BOT_TOKEN`, `ADMIN_IDS`
   (свой Telegram ID — [@userinfobot](https://t.me/userinfobot)) и `WEBAPP_URL`.
4. Установи зависимости и запусти:

```bash
pip install -r requirements.txt
python bot.py
```

## Деплой на Railway

Нужен публичный HTTPS-адрес — на нём одновременно висят мини-апп капчи и вебхук от Telegram.
Без него бот при старте откажется работать.

1. Задеплой сервис из GitHub-репозитория (Railway подхватит `Dockerfile`).
2. Settings → Networking → **Generate Domain**. Railway выдаст домен вроде
   `https://твой-сервис.up.railway.app` и сам пробросит порт через `PORT`.
3. Скопируй домен в `WEBAPP_URL` (с `https://`, без слэша на конце).
4. Заполни остальные переменные из `.env.example`.

### Volume — обязательно, если важно не терять данные между редеплоями

Без подключённого диска файловая система контейнера **пересоздаётся при каждом редеплое** —
пропадут список участников, баны, доверенные, статистика, настройки капчи по чатам. Только
список чатов (Каналы/Группы) можно будет восстановить кнопкой «➕ Добавить», остальное — нет.

1. В сервисе на Railway: **New → Volume**, смонтируй на `/data`.
2. В переменных окружения поставь `DB_PATH=/data/bot.db`.
3. Редеплой — дальше база живёт на диске и пересоздание контейнера её не трогает.

```bash
# локальный запуск в докере, если нужно
docker build -t anti-raid-bot .
docker run --env-file .env -p 8080:8080 -v $(pwd)/data:/data anti-raid-bot
```

## Все переменные окружения

| Переменная | Что делает |
|---|---|
| `BOT_TOKEN` | Токен от BotFather |
| `ADMIN_IDS` | ID владельца(ев) через запятую |
| `DB_PATH` | Путь к SQLite-базе (на Railway — `/data/bot.db` с Volume) |
| `WEBAPP_URL` | Публичный HTTPS-адрес (обязателен) |
| `PORT` | Порт веб-сервера (на Railway — автоматически) |
| `WEBHOOK_SECRET` | Секрет пути вебхука (можно оставить пустым — сгенерируется сам) |
| `OWNER_CONTACT` | Кого показывать посторонним вместо панели в личке |
| `RAID_JOIN_THRESHOLD` / `RAID_WINDOW_SECONDS` | Порог и окно детекта накрутки |
| `RAID_CAPTCHA_DURATION` | На сколько секунд включать капчу автоматически при рейде |
| `EXTREME_RAID_WINDOW_SECONDS` / `EXTREME_RAID_THRESHOLD` | Порог экстренного авто-бана всплеска |
| `CAPTCHA_TIMEOUT_SECONDS` | Сколько времени на решение капчи |
| `REQUEST_DECLINE_SECONDS` | Через сколько отклонять зависшую заявку на канал |
| `CAS_ENABLED` / `CAS_API_URL` / `CAS_TIMEOUT_SECONDS` | Проверка по базе CAS |
| `HEURISTICS_ENABLED` | Капча подозрительным даже при общей капче выкл. |
| `FLOOD_WINDOW_SECONDS` / `FLOOD_MESSAGE_THRESHOLD` / `FLOOD_REPEAT_THRESHOLD` / `FLOOD_MUTE_SECONDS` | Антифлуд |
| `EMOJI_WAVE_ID` / `EMOJI_CHECK_ID` / `EMOJI_GHOST_ID` | ID премиум-эмодзи в капче (нужен Premium у владельца, иначе тихий откат на обычные) |

## Заметки

- **Список участников, баны, доверенные, статистика — только с момента, как бот стал
  админом чата.** У Telegram Bot API нет метода «показать всех, кто уже состоит в чате» —
  это ограничение платформы, не баг бота.
- Счётчик вступлений для антирейда, сессии капчи и счётчики антифлуда — в памяти процесса,
  обнуляются при рестарте (это нормально, не должны жить вечно).
- Бот работает с любым числом чатов/каналов одновременно — у каждого свои настройки, статус,
  список участников и баны. Доверенные пользователи — общие для всех чатов сразу.
